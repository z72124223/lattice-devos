## Objective

Produce the first runnable segment of the delivery-first product path. A Rust
entry accepts a bounded task, records intent in real PostgreSQL, supervises the
official Codex app-server to modify an isolated Git repository, runs the fixed
verification command, creates a local commit, records the terminal result, and
can replay status from PostgreSQL.

## Acceptance Criteria

- [ ] A new `lattice-runtime` executable exposes a bounded local command and an
  MCP stdio surface suitable for Codex App registration; this does not expand
  the read-only `lattice-cli` contract.
- [ ] The Codex adapter captures exact executable path, version, SHA-256, and a
  schema digest generated by that same binary before starting a task.
- [ ] The adapter owns a real `codex app-server --listen stdio://` process,
  initializes it, starts one bounded thread/turn, observes an unambiguous
  terminal result, and can interrupt or fail closed.
- [ ] The acceptance path uses a newly created isolated Git repository, permits
  only its declared file, runs a fixed local test, rejects foreign changes, and
  creates a real local commit only after verification passes.
- [ ] Intent, component identity, changed-path/test/commit evidence, and the
  terminal outcome are stored in a real marker-owned PostgreSQL instance and
  reloaded by a separate status invocation.
- [ ] Process loss, timeout, malformed protocol, failed test, scope drift, Git
  ambiguity, or database ambiguity never reports success; uncertain effects
  become reconciliation-required.
- [ ] A repeatable PowerShell acceptance command proves the full TASK-032 path
  from a clean checkout and emits machine-readable evidence.

## Non-Goals

- Claim that MVP-1 is complete before real OpenClaw, Graphify, Hermes, and
  Codebase Memory nodes join the same executable path.
- Mutate an existing user product repository in this first acceptance run.
- Push, merge the primary branch, publish, deploy, pay, expose a public service,
  or activate self-upgrade authority.
- Finish paused TASK-022 governance or add unrelated documentation.

## Module And Constitution Constraints

- `codex-adapter` 1.0 owns only Codex process/protocol identity and typed
  evidence; it cannot call Git, tests, PostgreSQL, or another adapter.
- `orchestrator-runtime` 2.0 owns effect ordering and persists intent before the
  Codex, verification, and Git effects.
- `postgres-store` 1.4 remains the only durable task/result truth used here.

## TDD Behaviors

1. RED/GREEN: a scripted app-server proves framing, request correlation,
   terminal detection, timeout, EOF, malformed JSON, and interruption.
2. RED/GREEN: an isolated Git fixture permits one declared change, rejects a
   foreign path, runs a fixed test, and commits only the passing state.
3. RED/GREEN: PostgreSQL intent and terminal evidence survive a new process and
   status replay; ambiguous writes do not become success.
4. LIVE: the official Codex app-server completes the isolated change and the
   combined acceptance command reports the durable commit evidence.
